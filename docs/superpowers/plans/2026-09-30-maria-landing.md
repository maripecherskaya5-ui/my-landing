# План реализации «Мария / цифровая мастерская»

> Для исполнителя: после выбора Марии выполнять задачи по навыку `superpowers:executing-plans` либо `superpowers:subagent-driven-development`. Отмечать выполненные шаги флажками. Пояснения и пользовательские тексты — на русском.

**Цель:** создать адаптивный сайт Марии с семью секциями, демонстрационными концептами, примером подготовки брифа и формой с корректными состояниями.

**Архитектура:** содержание находится в статическом HTML и читается без JavaScript. Небольшие модули отвечают за меню, демонстрацию и форму. Локальный сервер раздаёт только папку `public`; настоящая доставка обращения отделена от предпросмотра.

**Технологии:** HTML, CSS, JavaScript с модулями; доступный Node.js 24 и его встроенные средства тестирования. Тяжёлый клиентский фреймворк не требуется.

**ТЗ:** [specification.md](../../../specification.md), согласовано 30 сентября 2026 года. Исследование: [research.md](../../../research.md).

**Статус:** план подготовлен и проверен по ТЗ; код ещё не создан. Ожидается проверка плана и выбор способа выполнения Марией.

## Кратко для Марии

Сначала соберём страницу с вашими текстами и оформлением. Затем добавим демонстрацию, раскрывающиеся разделы и форму. Проверим телефон, клавиатуру, ошибки и отсутствие ложной отправки. Вы получите локальный просмотр и инструкцию. Для настоящих обращений позднее понадобятся рабочий контакт и настройка доставки сообщений.

Рекомендую реализацию в текущем чате с независимой итоговой проверкой отдельным агентом. Для небольшой страницы это проще, чем передавать каждый этап новому исполнителю. Альтернатива — отдельные агенты для реализации и проверки каждого этапа: больше промежуточных проверок, времени и ресурсов.

## Общие ограничения

- Название: «Мария / цифровая мастерская». Видимые тексты, сообщения, подписи доступности и инструкции — на русском.
- Реальных проектов пока нет: концепты явно подписаны. Не выдумывать клиентов, отзывы, цены, сроки, награды и показатели.
- Семь секций по ТЗ: первый экран, работы с демонстрацией, услуги, процесс, о Марии, вопросы и ответы, контакт. Шапка и подвал отдельно.
- Основные цвета: `#F7F7F7`, `#1E1E1E`, `#3454F5`; вторичный текст `#595C66`. Manrope с кириллицей и локальной лицензией; системный запасной шрифт.
- Контакт: 3–200 символов после удаления пробелов по краям. Задача: 10–3000. Два обязательных поля; имя и бюджет не запрашиваются.
- Пустой адрес обработчика означает предпросмотр: без отправки и без события заявки.
- Успех — только HTTP 2xx и JSON `{ "ok": true }`. Ожидание 15 секунд; ошибка, пустой ответ или HTML не считаются успехом.
- Не сохранять пользовательский текст в постоянное хранилище браузера, аналитику или открытые журналы. Секреты не находятся в публичных файлах.
- Предпросмотр закрыт от индексации. Нет фиктивного домена, пустых контактных ссылок и автоматической публикации.
- Цели реальных посещений: LCP ≤ 2500 мс, INP ≤ 200 мс, CLS ≤ 0,1 на 75-м перцентиле. До запуска это цели, не результаты.
- Начальный JavaScript ≤ 30 KB gzip, CSS ≤ 25 KB gzip; первая загрузка желательно ≤ 500 KB. Lighthouse: производительность ≥ 90, доступность ≥ 95 при наличии инструмента; ручная проверка отдельно.
- Проверить 320, 375, 768, 1024, 1440 px и масштаб 200%. Цели нажатия — минимум 44×44 px. Учитывать настройку уменьшенного движения.
- Нет заставок, автозвука, перехвата прокрутки и обязательного взаимодействия с демонстрацией.
- Git-репозитория пока нет. Сохранять файлы на каждом этапе; не заявлять о коммитах. Если репозиторий появится, фиксировать относящиеся изменения после проверки.

## Пять рисков для особого внимания

1. Отключён JavaScript: текст, ссылки и раскрытия работают; форма не отправляет данные неожиданным способом. Проверки этапов 1 и 4.
2. Служба отвечает медленно или неверно: поля сохранены, повторы блокируются во время запроса, ложного успеха нет. Этап 4.
3. Telegram, международный телефон, пробелы и Unicode: контакт не ограничен форматом email, пустой текст не проходит. Этап 4.
4. Узкий экран, длинная строка, увеличение текста: нет переполнений и недоступных действий. Этапы 2 и 5.
5. Запрос документации или пути вне публичной папки: сервер не выдаёт содержимое рабочего каталога. Этап 1.

## Этап 1. Страница и локальный запуск

**Создать:** `package.json`, `server.mjs`, `public/index.html`, `tests/server.test.mjs`.

**Использует:** тексты раздела 5 ТЗ.

**Предоставляет:** `createServer({ root } = {})` из `server.mjs` возвращает сервер Node.js; импорт не запускает прослушивание порта. При прямом запуске адрес `127.0.0.1`, порт из `PORT` либо 4173, корень — соседняя папка `public`. Разрешены GET и HEAD. Якоря: `home`, `work`, `services`, `process`, `about`, `faq`, `contact`.

- [ ] Написать тесты `servesLanding`, `blocksPrivatePaths`, `rejectsMethods`, `returnsNotFound`. Запускать сервер на свободном порту, закрывать после проверки. Утверждения: `/` → 200; HEAD → пустое тело; `/research.md`, `/specification.md`, `/.env`, закодированный выход из корня и символьная ссылка вне корня не выдают файл; POST → 405; неизвестный путь → 404. Использовать безвредные тестовые файлы.
- [ ] Выполнить `node --test tests/server.test.mjs`: ожидается падение из-за отсутствующей реализации.
- [ ] Реализовать сервер: нормализация и проверка реального пути, запрет скрытых сегментов и выхода из корня, корректные типы файлов и статусы, отсутствие листинга каталогов, обработка неверного кодирования URL.
- [ ] Создать HTML с одним H1 и полным содержанием семи секций: концепты, нативные раскрытия `details/summary`, постоянные подписи полей, пропуск навигации, `lang=ru`, метаданные, запрет индексации. Без JavaScript контактная кнопка изначально недоступна и есть пояснение; данные формы не отправляются через стандартный GET.
- [ ] Добавить команды: `npm run dev` → `node server.mjs`, `npm test` → `node --test`. Не устанавливать зависимости приложения без необходимости.
- [ ] Повторить тесты: ожидается ноль ошибок. Проверить чтение страницы и раскрытие ответов без JavaScript. Сохранить этап.

**Критерии ТЗ:** A01, A02, A03, A05, часть A13.

## Этап 4. Форма с честным предпросмотром

**Создать:** `public/config.js`, `public/core.js`, `tests/core.test.mjs`. **Изменить:** `public/app.js`, HTML и CSS.

**Использует:** форму `#contact-form`, поля `contact`, `task`, отдельные сообщения ошибок и область состояния.

**Предоставляет:**

- `config = { leadEndpoint: '', email: '', telegramUrl: '' }`; пустые контакты не показываются как ссылки.
- `validateLead(input)` → `{ valid, values: { contact, task }, errors: { contact?, task? } }`. Проверять типы до удаления пробелов. Длина — число символов Unicode через `Array.from`, не байтов.
- `submitLead(values, { endpoint, fetchImpl = fetch, timeoutMs = 15000 })` → обещание `{ status, message }`. Статусы: `preview`, `success`, `error`, `rate_limited`. Нет изменения страницы и записи данных внутри этой функции.
- `track(name, metadata = {})` в `app.js` создаёт локальное событие `landing:analytics` только с параметрами `section` и `scenario`. Внешнего получателя нет.

- [ ] Написать тесты `validatesBoundaries`, `rejectsWhitespaceAndNonStrings`, `acceptsContactFormats`: длины контакта 2/3/200/201, задачи 9/10/3000/3001, пробелы, `null`, число, email, Telegram, международный телефон и Unicode. Допустимые границы проходят, остальные дают ошибку.
- [ ] Написать тесты отправки: пустой адрес → `preview` и ноль вызовов сети; 200 + `{ok:true}` → `success`; 200 + `{ok:false}`, 204, HTML, 400, 500 и обрыв → `error`; 429 → `rate_limited`; превышение ожидания прерывает запрос. Подмена сетевой функции не обращается к реальным получателям.
- [ ] Запустить `node --test tests/core.test.mjs`: подтвердить падение до реализации.
- [ ] Реализовать проверку и отправку. Адрес допускается только как путь того же сайта с `/`, но не `//`; прочие адреса дают ошибку без запроса. Использовать `AbortController`, очищать таймер, передавать только `{contact, task}`. Не показывать внутренние сообщения сервера.
- [ ] Подключить форму: кнопка становится доступной после подключения обработчика, русские ошибки вместо стандартных сообщений браузера, фокус на первом ошибочном поле, ошибки связаны через `aria-describedby`. Во время запроса кнопка заблокирована. Значения сохраняются после ошибки и проверки; после настоящего успеха повтор блокируется до изменения данных.
- [ ] Показать предупреждение предпросмотра перед полями и кнопку «Проверить заполнение». После проверки: «Поля заполнены. Это предпросмотр — сообщение не отправлено». В этом состоянии нет события `generate_lead`.
- [ ] Добавить события из ТЗ: `case_open`, `demo_select`, `contact_click`, `form_start` один раз при начале ввода, `form_error`, `generate_lead` только после `success`. Ни контакт, ни задача не включаются в параметры.
- [ ] Повторить тесты и вручную проверить двойное нажатие, сетевую ошибку, сохранение ввода, русские сообщения и отсутствие запросов в предпросмотре. Сохранить этап.

**Критерии ТЗ:** A06–A09, часть A11. Подмена успешного ответа в тесте не доказывает настоящую доставку.

## Этап 6. Подготовка к публичному запуску

Зависит от сведений Марии и не блокирует локальную версию. Публикация не выполняется автоматически.

**Файлы:** после выбора инфраструктуры — конфигурация, метаданные HTML, документы для посетителей, файлы хостинга, README и результаты проверки.

**Использует:** подтверждённый контакт, домен, условия работы и выбранный сервис доставки. Не создавать фиктивный обработчик, всегда отвечающий успехом.

- [ ] Получить рабочий email или Telegram, подтвердить предложенные условия работы, выбрать домен/хостинг. Реальные кейсы не являются обязательным условием запуска.
- [ ] Подготовить конкретный план обработчика под выбранный сервис: проверка полей, ограничение размера/частоты, надёжный приём, предотвращение дублей, хранение/удаление, секреты только на сервере. Согласовать расходы при их появлении.
- [ ] Подготовить сведения об обработке данных для фактического владельца и сервиса; добавить рабочий альтернативный контакт.
- [ ] Проверить настоящую заявку, сбой и повтор после задержки; Мария подтверждает получение. Только после этого считать канал рабочим.
- [ ] Указать реальный адрес и изображение для ссылок, настроить HTTPS и заголовки хостинга, снять запрет индексации при готовности. Не включать исследование, ТЗ и секреты в опубликованные файлы.
- [ ] Показать точную итоговую версию и адрес перед публикацией. После разрешения опубликовать и проверить действующий сайт и доставку.
